# D5: Main loop and game flow

Log for D5 (ROADMAP). Subsystem map, unit boundaries, progress and open questions, as `d4.md` does for D4.

## Step 1: `tools/bo2map.py` (2026-10-08)

Spec `docs/superpowers/specs/2026-10-08-bo2map-design.md`, plan `docs/superpowers/plans/2026-10-08-bo2map.md`.
`tools/bo2src.py` reads a [b3dllc/burnout2](https://github.com/b3dllc/burnout2) checkout (kept outside the repo):
its game functions (bodies found under the `// 0xSTART - 0xEND` comments in `src/gamesource`, `src/GameShared`,
`src/nodebug`; 1,899 functions), the names their bodies call, their string and float literals, and vtable slot order
from `include/types/*.h` (inherited slots resolved). `tools/bo2map.py` pairs them with Burnout 3 game functions:
seeds (our adopted names, unique shared strings/floats, vtables whose slot sizes fit one class by a clear margin),
then link order (global address order, so our unit cuts don't box it in), vtable slots, callees and callers, to a
fixpoint. Tests: `python3 tools/test_bo2map.py` (12, synthetic). Run: `python3 tools/bo2map.py --bo2 PATH` (2.3 s),
`--unit UNIT`, `--eval`.

First run (138 rows): high 42, medium 37, low 59 (35 conflicts).

- Hold-out check (`--eval`): with one unit's names removed at a time, `d4/fs` comes back 16/17, `d4/pool` 0/8 and
  the load queue 0/4 (islands: nothing else anchors them); **0 wrong**.
- Spot check: all 13 non-seed `high` rows are consistent with Burnout 2's bodies (callees line up, e.g.
  `viBufCreate` → `viBufReset`, `CGTFilePS2DVD::Open` → `BuildFileName`/`GetFileNameFromDeviceName`, `CGame::Init`
  → `SetAsDefaultFilesystem`/`InstallToRenderWare`).
  - `unit_001D2EE0` = `CGTFileSystemPS2DVD`/`CGTFilePS2DVD`.
  - `unit_003248F0` = `CGTMpegManager`/`CGTMpegDecoder` + `viBuf*` (`vibuf.c`).
  - `func_001D41E0` = `CGame::Init`.
- `medium` rows are mixed (e.g. `COnePlayerCRASH::Update` proposed inside the force-feedback unit); treat them as
  leads to verify, not names.
- Why coverage is modest: Burnout 3 retail kept few strings (253 game functions reference any; 6 shared with Burnout
  2, 2 unique on both sides), 11 unique shared `.lit4` floats, and only ~70 named game functions to seed from. Sizes
  alone don't discriminate (8-byte stubs fit anything). Coverage grows with every unit we name: re-run after naming.
- Side finding: the tool also pairs unnamed kernel calls (`viBuf*` call `0x10BE40`/`0x10BE60` where Burnout 2 calls
  `WaitSema`/`SignalSema`; `0x114E60`/`0x114EB8` ↔ `DIntr`/`EIntr`). Vendor names are out of scope here.

## Boot and main loop (Burnout 3)

`main` is `func_0012EB30` (`game/unit_0012EB30`, 0x3C0), called from crt0. It sets up the big game object
`D_004EE040` and drives it: `func_00133BB0` (init), `func_00133190` (repeated until it returns non-zero: loading),
`func_00132600` (repeated until the byte at `0x51BA90` is set: the main loop), then `func_00132560` and
`func_00132420` (shutdown). All five are in `game/unit_00131D20` (16 functions, 0x131D20–0x134260), the game
object's file. Start-up also calls `func_00131AC0` eight times.

| Unit | Functions | State | Notes |
|---|---|---|---|
| `d5/unit_00131AC0` (0x131AC0–0x131CE0) | 4 | **linked** (4/4) | `.cpp` for one virtual call (slot +0x10 of the object at `0x1EA2970`); its `.sdata` (0.4f, 1.0f) stays in assembly. `func_00131B30` picks the number separators by language (`D_004E2918`, the language index: 5/6/10 use `.` and `,`, 4 uses space); `func_00131B90` scales a rate by the PAL/NTSC line rate (15.625/15.734 kHz) and the frame time `D_004F509C` (0.04/1/30/0.02 s); `func_00131CA0` tests whether the game object's pointer at `+0x2DA48` is `D_0051AEC0`. |

A data label `D_001320D8` sits inside `func_00132090` (check when linking). |

## Open questions

- `unit_00134570` is **not** `CGameMode` (the handoff's guess): it is mostly 8-byte default virtuals shared by a
  family of 65–68-slot vtables (0x38xxxx–0x39xxxx, a physics/object hierarchy the tool relates to `CVehiclePhysics`
  and `CCollidingBody`). The game-mode vtable at 0x4DDD90 (`gamemode.cpp`, 8 slots, ending in a 0xC/0x8 pair like
  Burnout 2's `Pause`/`Resume`) has its own functions in `unit_0013C940`; its base class is still to be found.
